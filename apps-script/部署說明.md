# LINE Gemini Bot：Apps Script 部署

這是目前 Python/Render 機器人的 Apps Script 移植版。請先保留 Render 服務，等 Apps Script 部署並通過 LINE Verify、實際訊息測試後，再考慮切換 Webhook。

## 1. 建立 Apps Script 專案

1. 開啟 [Google Apps Script](https://script.google.com/home) 並登入。
2. 選「新增專案」，把 `Code.gs` 全部內容貼到編輯器。
3. 儲存專案。

## 2. 設定金鑰

在 Apps Script 左側齒輪「專案設定」→「指令碼屬性」新增：

| 屬性 | 值 |
| --- | --- |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developers Console 的 Channel access token |
| `GEMINI_API_KEY` | Google AI Studio 的 Gemini API key |

選填：

| 屬性 | 用途 |
| --- | --- |
| `GEMINI_MODEL` | 模型名稱；預設 `gemini-3.8-flash`。若帳號不支援，需換成 API 可用的模型 |
| `WEBHOOK_ACCESS_KEY` | 必填。自訂長隨機字串，降低陌生請求；部署網址需加上 `?k=同一字串`。這不是 LINE 簽章驗證的替代品 |

不要把金鑰貼進 `Code.gs`、GitHub、LINE 聊天或公開文件。`WEBHOOK_ACCESS_KEY` 請自行產生一段長隨機字串，並在網址只加上 `?k=同一字串`。LINE Channel Secret 不需貼進此程式：Apps Script Web App 的 `doPost(e)` 事件沒有提供一般 HTTP headers，因此無法在此驗證 LINE 的 `X-Line-Signature`；網址金鑰只是降低陌生請求的風險，並非等同簽章驗證。

## 3. 部署成 Web App

1. 右上「部署」→「新增部署」。
2. 類型選「網頁應用程式」。
3. 「執行身分」選「我」；「誰可以存取」選「任何人」。
4. 按「部署」，完成 Google 授權後複製以 `/exec` 結尾的網址。
5. 若設定 `WEBHOOK_ACCESS_KEY`，Webhook 網址格式為 `https://script.google.com/macros/s/部署代碼/exec?k=你的長隨機字串`。

LINE 的 Webhook URL 必須是部署產生的 `/exec` 網址，不是編輯器網址。Apps Script 的 Content Service 會將回應導向 Google 的內容網址，LINE 驗證器不接受這個 302 轉址。本專案改用 `HtmlService.createHtmlOutput()` 回應 Webhook，避免 Content Service 的轉址。

## 4. 驗證與切換

1. 到 LINE Developers Console → Messaging API，將 Apps Script `/exec` 網址（含 `?k=` 存取參數）設為 Webhook URL，按 Verify。
2. Verify 成功後，確認「Use webhook」已開啟，再從 LINE 傳 `/ping`、`早安`、`/help` 和一般問題測試。
3. 若 Verify 失敗或訊息沒有回覆，先把 Webhook URL 改回 Render 的舊網址，避免機器人中斷；再查看 Apps Script「執行項目」的錯誤紀錄。

- 部署 ID、Webhook URL 中的 `WEBHOOK_ACCESS_KEY` 和所有 API 金鑰不放入此 GitHub 專案；請在 Apps Script 指令碼屬性與 LINE Developers Console 管理。

## 注意

- Apps Script 免費帳號有每日服務配額；Gemini API 另有自己的模型、速率和用量限制。Apps Script 不會讓 Gemini 搜尋自動免費，也不會沿用 Gemini 會員方案配額。
- 本版會在 LINE Webhook 請求期間同步呼叫 Gemini 再回覆，Gemini 太慢時 LINE 可能逾時。Apps Script Web App 也無法讀取 LINE 簽章標頭，因此部署前要先評估這項安全與穩定性限制；Render 原服務保留作回復方案。
- 對話記憶與教師資料快取存在 Apps Script Cache，會過期且不保證永久保存。
